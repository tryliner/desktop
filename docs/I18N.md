# Translations

Liner ships in 12 languages: en, ru, uk, es, de, it, fr, pl, tr, pt, id, vi. English is the
source and the fallback for every other language.

## How it works

- Strings live in `src/languages/locales/<locale>.json` as nested objects
  (`"library": { "local": { "title": "On this device" } }`).
- `src/languages/translator.ts` flattens them into dot keys (`library.local.title`).
- Components call `const { t } = useTranslation()` from `@/languages`, then
  `t("library.local.title")`. Outside React (stores, toasts from the engine) use
  `createTranslatorSync(getStoredLocale())`.
- Lookup order: the current locale, then English, then the key itself.
- The chosen language is saved in `localStorage` as `liner_locale`. On first launch it is
  taken from the system languages; `ua` is read as `uk`.

## Adding or changing a string

1. Add the key to `en.json` first. That alone makes it work everywhere.
2. Add the same key to the other locales you can write well. Missing keys fall back to
   English; a wrong translation is worse than an English one.
3. Put the key in the section of the screen it belongs to (`library`, `player`,
   `settings.youtube`, ...). Use `common` only for words used on many screens.
4. Keep `{placeholders}` exactly as in English.

A missing key renders as the key itself (`library.local.title`), so `t("x") || "Text"`
never falls back. Add the key to `en.json` instead of relying on `||`.

## Variables and plurals

```ts
t("library.local.imported", { count: 3 });
```

When `count` is a number, the translator first looks for a plural form chosen by
`Intl.PluralRules` for the current language, then `<key>_plural`, then the plain key:

| Language       | Forms to provide                                        |
| -------------- | ------------------------------------------------------- |
| en, de, tr     | `_one`, `_other`                                        |
| es, it, fr, pt | `_one`, `_other`, and `_many` (used for round millions) |
| ru, uk, pl     | `_one`, `_few`, `_many`, `_other`                       |
| id, vi         | `_other`                                                |

A missing form does not fall back to `_other`: it goes to `<key>_plural` and then the
plain key. Provide every form in the table, or add a `<key>_plural` as a catch-all.

```json
"imported_one": "Добавлена {count} песня",
"imported_few": "Добавлено {count} песни",
"imported_many": "Добавлено {count} песен",
"imported_other": "Добавлено {count} песен"
```

Other `{name}` variables are replaced as plain text.

## Adding a language

1. Copy `en.json` to `src/languages/locales/<code>.json` (two-letter ISO 639-1 code) and
   translate it. Translate every key, including `settings`, `youtube_auth` and `toast`.
2. Add the code to `SUPPORTED_LOCALES` in `src/languages/locale.ts`.
3. Import the file in `src/languages/data.ts` and add it to `translations`.
4. Add a picker entry in `src/languages/options.tsx` with the name written in that
   language and its flag.
5. Run `pnpm test src/languages`. The "registered locales" test fails if a locale is
   missing its file or its picker option.
6. Switch to the language in Settings and look at the main screens: home, search,
   library, a playlist, the player, settings. Long words break layouts; shorten where
   needed instead of shrinking fonts.

## Style

- Write the way the app talks in English: short, plain, no exclamation marks.
- Keep product names as they are: Liner, YouTube, YouTube Music, Discord, SoundCloud.
- Use the informal "you" where the language has a choice (ты, ти, du, tu).
- Do not machine-translate a whole file and send it unread. Reviewers check translations
  against English, and a PR that is obviously unread will be closed.
